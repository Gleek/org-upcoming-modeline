#+TITLE: org-upcoming-modeline

[[https://melpa.org/#/org-upcoming-modeline][https://melpa.org/packages/org-upcoming-modeline-badge.svg]]
[[https://stable.melpa.org/#/org-upcoming-modeline][https://stable.melpa.org/packages/org-upcoming-modeline-badge.svg]]

This package shows you the next upcoming org appointment in your modeline.

* Note on this fork

Fork of [[https://github.com/unhammer/org-upcoming-modeline][unhammer/org-upcoming-modeline]]. Changes on top of upstream:

- =org-upcoming-modeline-show-running= (on by default here): count down the
  end of the time-block you are currently inside, instead of always
  showing the next event. Handover to the next block is based on how
  close /its/ start is (within =org-upcoming-modeline-switch-ahead=
  seconds), not on how much is left of the current one -- so a gap
  between blocks shows nothing rather than a stale countdown. Set it to
  nil for the upstream behaviour of always showing the next event. See
  [[#configuration][Configuration]] below.
- =org-upcoming-modeline-show-seconds= (nil by default here): durations are
  shown as "1m" rather than "1m30s", so the mode line stops twitching
  every few seconds. Set it to t for the upstream behaviour.
- The default format is padded on both sides, so it no longer runs into its
  neighbours in =global-mode-string= (the org clock, for one).

None of this is proposed upstream yet. Until then, install from here
instead of MELPA:

#+begin_src emacs-lisp
  ;; elpaca
  (use-package org-upcoming-modeline
    :ensure (:fetcher github :repo "Gleek/org-upcoming-modeline")
    :config
    (org-upcoming-modeline-mode))

  ;; straight.el
  (use-package org-upcoming-modeline
    :straight (org-upcoming-modeline :host github :repo "Gleek/org-upcoming-modeline")
    :config
    (org-upcoming-modeline-mode))
#+end_src


You can left-click on it to go to it, right-click for a menu of
actions, middle-click to temporarily hide it.

* Installation

** MELPA
If you use [[https://melpa.org/][MELPA]], you can do =M-x list-packages=, find
=org-upcoming-modeline= in the list and hit =i x=.

** Manual
Just put =org-upcoming-modeline.el= somewhere in =load-path=.

* Configuration
** Basic
#+begin_src emacs-lisp
  (use-package org-upcoming-modeline
    :after org                               ; if you don't want it to start until org has been loaded
    :load-path "~/src/org-upcoming-modeline" ; if you installed manually
    :config
    (org-upcoming-modeline-mode))
#+end_src
** Advanced
You can generate a description of all the avaiable functionalites and display it from GNU Emacs by doing =M-x customize-group RET org-upcoming-modeline=.

Here is a non-exhaustive list of some =org-upcoming-modeline= functionalities:

- =org-upcoming-modeline-ignored-keywords=  allows you to exclude TODO states.
  Example excluding "BACKLOG" and "NEXT" states:
  #+begin_src emacs-lisp 
    (setq org-upcoming-modeline-ignored-keywords '("BACKLOG" "NEXT")
  #+end_src
- =org-upcoming-modeline-format= allows you to modify the displaying format of the elements around the appointment time (=time-string=)  and the appointment title (=heading=).
  Example replacing the alarm clock icon with a calendar icon, and replacing =:= with =-=:
  #+begin_src emacs-lisp 
    (setq org-upcoming-modeline-format (lambda (ms mh) (format "🗓 %s - %s" ms mh)))
  #+end_src
- =org-upcoming-modeline-show-seconds= controls whether durations keep their
  seconds part. Nil (the default in this fork) turns "1m30s" into "1m";
  durations under a minute still show seconds, there being nothing else to
  show. The tooltip always spells the duration out in full.
  #+begin_src emacs-lisp
    (setq org-upcoming-modeline-show-seconds t) ; upstream behaviour
  #+end_src
- =org-upcoming-modeline-days-ahead= allows you to fix the number of days to look into the future (1 by default).
  Example looking for 15 days ahead:
  #+begin_src emacs-lisp 
    (setq org-upcoming-modeline-days-ahead 15)
  #+end_src
- =org-upcoming-modeline-trim= allows you to fix the number of characters displayed for the appointment title (=heading=), it is 20 by default.
  Exemple removing the trimming:
  #+begin_src emacs-lisp
    (setq org-upcoming-modeline-trim nil)
  #+end_src
- =org-upcoming-modeline-show-running= makes the modeline count down the
  /end/ of the event you are currently inside, rather than jumping straight
  to the next one. It only applies to events with a same-day time range,
  like =<2024-05-05 Sun 10:00-11:30>=. A running event is shown with =▶=
  instead of =⏰=; =org-upcoming-modeline-running-p= tells a custom
  =org-upcoming-modeline-format= function which of the two it is rendering.

  The handover to the next event is driven by how close /that event's
  start/ is, not by how much is left of the running one:
  - Inside an event, and the next one is more than
    =org-upcoming-modeline-switch-ahead= seconds away (15 minutes by
    default): show the running event, counting down to its end.
  - The next event's start is within that many seconds, whether or not
    something is currently running: show the next event.
  - Nothing running, and the next event is further away than that: show
    nothing. In particular, a gap between two events longer than
    =switch-ahead= means a blank modeline in between, rather than either
    event.
  #+begin_src emacs-lisp
    (setq org-upcoming-modeline-switch-ahead (* 10 60)) ; hand over 10 min out, not 15
    (setq org-upcoming-modeline-show-running nil)       ; or turn the whole thing off
  #+end_src
  On by default in this fork. Running events are looked for up to
  =org-upcoming-modeline-lookback= seconds back (8 hours), so events longer
  than that are not detected.

* Related packages

** appt

=appt= is not itself integrated with org-mode, but if you do
=(add-hook 'org-finalize-agenda-hook #'org-agenda-to-appt)= it will
add appointments from that agenda to your list of future warnings, and
warn when you're getting closer. But the modeline just says "App't in
15 min." (it doesn't show the name of the event, and there's no
org-integration). However, by default it will keep popping up a small
window with the event name for you every so often when the event is
getting near.

In comparison, this package doesn't require you to open (the correct)
=org-agenda= first; it shows the actual org heading and adds
org-specific "actions" that you can select for the event. And since it
uses =org-ql=, it'll automatically remove the event (after a short
idle delay) if you remove it from your org file.
